# قصة جماعية — Realtime Collaborative Story Game

لعبة جماعية لحظية: ينضمّ اللاعبون إلى غرفة من أجهزتهم، ويكتبون قصة معًا **جملة واحدة لكل لاعب بالترتيب**، ثم تُكشف القصة كاملة ويُصوّت الجميع (بشكل مجهول) لأفضل جملة. الجملة الأكثر أصواتًا تفوز.

- واجهة **عربية بالكامل، من اليمين لليسار (RTL)، مصمّمة للهاتف أولًا**.
- جوّ **سينمائي درامي**: خلفية داكنة، سبوت لايت على الجملة النشطة، عدّاد تنازلي متوتر، مؤثرات typewriter عند الكشف، كونفيتي للفائز، تفاعلات إيموجي طافية، ومؤثرات صوتية مُولّدة بالكامل (Web Audio).

---

## التشغيل محليًا

المتطلبات: Node.js 18 أو أحدث.

```bash
npm install
npm start
```

ثم افتح `http://localhost:3000` في المتصفح. للّعب التجريبي على جهاز واحد، افتح **3 تبويبات** على الأقل (أو شارك الكود مع أصدقائك على الشبكة نفسها).

- المنفذ يُقرأ من `process.env.PORT` (الافتراضي `3000`)، والخادم يستمع على `0.0.0.0`.
- فحص الصحّة: `GET /health`.

### كيف تلعب
1. اكتب اسمك ثم **أنشئ غرفة** (تصبح المضيف) أو ادخل بكود غرفة موجودة.
2. في الردهة: المضيف يختار **جملة بداية** (جاهزة أو مخصّصة) ثم يضغط **ابدأ اللعبة** (يلزم ٣ لاعبين على الأقل، ٧ كحدّ أقصى).
3. يكتب كل لاعب جملة واحدة في دوره خلال **٣٠ ثانية** (انتهاء الوقت = تخطّي).
4. المضيف **يكشف القصة**، ثم **يفتح التصويت**.
5. يصوّت كل لاعب لجملة (ليست جملته). الأكثر أصواتًا يفوز — وعند التعادل تُجرى **جولة حسم واحدة**، وإن استمر التعادل فهو **فوز مشترك**.

## النشر على Railway

1. ادفع المشروع إلى مستودع Git (GitHub مثلًا).
2. في [Railway](https://railway.app): **New Project → Deploy from GitHub repo** واختر المستودع.
3. لا حاجة لأي إعداد خاص:
   - `npm install` يُشغَّل تلقائيًا.
   - أمر التشغيل هو `npm start` (المعرّف في `package.json`).
   - Railway يحقن متغيّر `PORT` تلقائيًا، والخادم يقرأه من `process.env.PORT` ويستمع على `0.0.0.0`.
4. بعد النشر، استخدم الدومين العام الذي يوفّره Railway.

> Socket.IO يعمل عبر WebSocket/long-polling على المنفذ نفسه — لا حاجة لإعداد إضافي على Railway.

## التوسّع لأكثر من خادم واحد (لاحقًا)

كل حالة اللعبة محفوظة **في الذاكرة** داخل عملية الخادم (Map)، واللعبة عابرة وتعمل على **نسخة خادم واحدة**. للتوسّع أفقيًا على أكثر من نسخة لاحقًا، أضِف موزِّع Redis لـ Socket.IO حتى تتزامن الأحداث بين النسخ:

```bash
npm install @socket.io/redis-adapter redis
```

```js
const { createAdapter } = require('@socket.io/redis-adapter');
const { createClient } = require('redis');
const pub = createClient({ url: process.env.REDIS_URL });
const sub = pub.duplicate();
await Promise.all([pub.connect(), sub.connect()]);
io.adapter(createAdapter(pub, sub));
```

> ملاحظة: حالة الغرف الحالية (الـ Map) ستظل بحاجة إلى مخزن مشترك أيضًا عند التوسّع. **لا تُضِف هذا الآن** — المشروع مصمّم عمدًا لنسخة واحدة.

## البنية

```
server.js          # Express + Socket.IO، كل منطق اللعبة، غرف في الذاكرة (مصدر الحقيقة الوحيد)
public/index.html  # صفحة واحدة، dir="rtl" lang="ar"
public/style.css   # ثيم داكن سينمائي، RTL، للهاتف أولًا
public/app.js      # عميل السوكِت، توجيه الشاشات، الرسم من الحالة، العدّاد التنازلي
public/effects.js  # طبقة المؤثرات: بطاقات الأدوار، السبوت لايت، الكونفيتي، الإيموجي الطافي، الـ typewriter
public/audio.js    # مؤثرات صوتية مُولّدة عبر Web Audio + كتم الصوت
README.md
```

### مبادئ التصميم
- **الخادم هو مصدر الحقيقة الوحيد.** العملاء لا يحسبون منطق اللعبة؛ يرسلون نوايا المستخدم ويعرضون حالة الخادم فقط.
- العدّاد التنازلي **موثوق من الخادم**: يُرسَل وقت الانتهاء (deadline) مرة واحدة، والعميل يعرض العدّ محليًا منه (لا نبض كل ثانية من الخادم).
- يُتحقَّق من **كل شيء** على الخادم: الطور، ملكية الدور، صلاحيات المضيف، منع التصويت المزدوج أو التصويت للذات.
- إعادة الاتصال: يُخزَّن `{ roomCode, playerId, name }` في `localStorage`، وتُحاوَل العودة تلقائيًا خلال مهلة سماح ٣٠ ثانية. عند خروج المضيف نهائيًا، يُرقّى أقدم لاعب متصل مضيفًا.

### إمكانية الوصول والأداء
- زرّان دائمان (يُحفظان في `localStorage`) في الزاوية العلوية على كل الشاشات: **كتم الصوت** 🔊/🔇 و**تقليل الحركة** 🎞️.
- يُحترَم `prefers-reduced-motion`: تُستبدل الحركة بظهور فوري بسيط، وتُعطَّل آلة الكاتبة والكونفيتي والإيموجي الطافي (يظهر عدّاد ثابت بدلًا منه).
- المؤثرات تُحرّك `transform` و`opacity` فقط، تعيش على طبقة overlay منفصلة، ولا تؤخّر عرض حالة اللعبة (الاستثناء الوحيد: تسلسل الكشف، وهو قابل للتخطّي). عدد الجسيمات/العُقد محدود وتُزال بعد انتهائها.
- الصوت يبدأ فقط بعد أول لمسة من المستخدم (سياسة التشغيل التلقائي للمتصفح).
